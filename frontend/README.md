# Фронтенд

Одностраничный интерфейс платформы: радар трендов (стартовая страница `/trends`), поиск и чат по
базе знаний, документы, цели и KPI, доска гипотез, админка. Маршруты — в
[src/app/App.tsx](src/app/App.tsx).

React 19, TypeScript 7, Vite 8, Tailwind CSS 4, React Router 7, i18next (`ru`, `en`, `zh`),
иконки Lucide, общие компоненты — `src/shared/ui`. Пакетный менеджер — Bun.

## Дизайн-система

- [DESIGN.md](../DESIGN.md) — визуальные правила, семантика цветов, типографика и композиция.
- [UI_KIT.md](docs/UI_KIT.md) — реестр компонентов, правила развития и проверки.
- [tokens.css](src/shared/design-system/tokens.css) — экранные токены;
  [colors.ts](src/shared/design-system/colors.ts) — адаптер Canvas и печатная палитра.

Живой каталог компонентов: `bun run ui-kit`, адрес `/ui-kit.html`. Он работает без бэкенда и
авторизации на реальных компонентах приложения.

Заставка поиска — трёхмерная библиотека (`src/features/trend/ui/library`). Мебель и персонажи
сгенерированы: концепты нарисованы генератором изображений, превращены в 3D (Tripo H3.1) и сжаты
`gltf-transform optimize --compress meshopt --texture-compress webp`; полы и ковры — сгенерированные
текстуры WebP. Сцена сначала строится процедурно, модели догружаются отдельным чанком.

## Локальная разработка

Нужны Bun 1.4.2 и Node 22.18 или новее для CLI-инструментов.

```bash
bun install
RAG_API=http://localhost:8080 bun run dev   # Vite проксирует /api на RAG_API
```

Из корня то же делает `make frontend-dev`.

## Проверки

```bash
bun run verify     # формат, линт, типы, Knip, audit, юниты, сборка, размер
bun run verify:ui  # то же плюс браузерные проверки UI kit и страниц продукта
```

Перед первым `verify:ui` на машине нужен `bunx playwright install chromium`. Отдельные команды —
в `package.json`, состав проверок и их границы — в [UI_KIT.md](docs/UI_KIT.md#контроль-качества).

`test:ui` проверяет каталог на ширинах 390/768/1024/1440 px и страницы продукта на 390/1440 px:
axe, клавиатуру, фокус, меню, формы, загрузку файлов, экспорт, ошибки и повторы. Страницы
работают на изолированной API-фикстуре с состоянием: неизвестный запрос или необработанная
ошибка страницы проваливают тест.

Доступность на живом стенде проверяет Playwright-аудит:

```bash
E2E_BASE_URL=http://localhost:5173 E2E_USER=admin E2E_PASS=<пароль> bun run a11y
```

Без `E2E_PASS` берётся `ADMIN_PASSWORD` из окружения.
