# Стык с ML: классификатор и источник кандидатов

Два места, где в радар встаёт модель ML-команды: классификатор слабых сигналов и извлечение
кандидатов сервисом `extractor` (последний раздел).

Интерфейс классификатора реализован. Когда адрес внешнего сервиса пуст, работает встроенная модель этапа 1 — логистическая регрессия ([train.py](../../scripts/weak-signal/train.py)). Артефакт ML-команды, подключённый по адресу, приоритетнее. Доля выполненных правил и проверки текстов языковой моделью этим классификатором не являются.

## Граница ответственности

Прикладной контур собирает открытые источники, выделяет предложения технологий, проверяет единство технологии и соответствие запросу, сохраняет подтверждающие фрагменты, формирует карточки и русские интерпретации. Только прошедшие эти проверки кандидаты поступают в модель. После inference выполняются финальное ранжирование, устранение повторов и ограничение до 15 результатов.

ML-команда владеет обучением, целевой меткой, артефактом, его версией, способом объяснения и калибровкой порога. Для интеграции не требуется менять сборщики, frontend, хранение выдачи или прикладные Go-модули. Сервис может быть реализован на Python с любым согласованным фреймворком.

## Подключение

В конфигурации `main-service` задаются:

```dotenv
RADAR_CLASSIFIER_URL=http://classifier:8080/predict
RADAR_CLASSIFIER_VERSION=weak-signal-2026-09-17.1
```

URL — полный внутренний адрес POST endpoint. Версия должна однозначно определять неизменяемый набор весов, препроцессинг и порог. HTTP timeout — 30 секунд, вход ограничен 4 МиБ, ответ — 1 МиБ; перенаправления запрещены. Весь шаг классификации ограничен 90 секундами. При смене версии прежний сохранённый результат не используется. Пустой URL включает встроенную модель: её версия берётся из артефакта, `RADAR_CLASSIFIER_VERSION` не читается. Недоступность или неверный ответ оставляет кандидатов без модельной оценки с видимой причиной; числовая оценка правил не подставляется вместо неё.

Встроенная модель числовые признаки из запроса не читает, а сама собирает их по фразе кандидата тем же кодом, что при обучении ([trend_live_classifier_embedded.go](../../backend/main-service/internal/application/trend_live_classifier_embedded.go)).

Ответ с `classifier_unavailable` не сохраняется как пригодный суточный результат и не принимается из старого кэша той же версии. Завершённая попытка доступна опросу 10 секунд, чтобы интерфейс получил причину без немедленного повторного запуска. После этого новый поиск повторяет весь прикладной конвейер, а не только inference; фонового повтора нет. Штатный режим `classifier_not_connected` кэшируется. Это поведение проверено регрессией с отказом и последующим восстановлением той же версии модели.

## Вход

Схема `weak-signal-features-v1`, один пакет на запрос. Источники кандидата прошли предварительную модельную проверку общего механизма; это не независимое подтверждение её правильности. Сведения об источниках — наблюдения доступного поискового окна, а не полный мировой корпус.

```json
{
  "feature_schema": "weak-signal-features-v1",
  "model_version": "weak-signal-2026-09-17.1",
  "query": "обнаружение синтетической речи при телефонном мошенничестве",
  "candidates": [
    {
      "id": "candidate-id",
      "name": "Русское название конкретной технологии",
      "features": {
        "documents": 4,
        "scientific_works": 3,
        "market_records": 1,
        "active_periods": 2,
        "author_groups": 3,
        "top_group_share": 0.33,
        "share_growth_pp": null,
        "first_observed": "2026-08"
      },
      "sources": [
        {
          "id": "source-id",
          "title": "Original source title",
          "abstract": "Observed source abstract, at most 2000 Unicode characters",
          "date": "2026-08-20",
          "url": "https://example.org/original-source"
        }
      ]
    }
  ]
}
```

Числа и адрес в примере условные и не являются результатом оценки. `null` у доли группы или роста означает отсутствие измерения; заменять его нулём нельзя. `first_observed` — первое наблюдение в доступном окне, а не доказанная дата изобретения. Группы авторов — наблюдаемые группы, их число не доказывает независимое воспроизведение. Вход не содержит итоговую эвристическую уверенность, присвоенную стадию, целевой класс или сгенерированное объяснение — их нельзя использовать как скрытую разметку.

## Выход

Один ответ на каждый входной ID, без пропусков, новых ID и повторов. Порядок произвольный. Имена модели, версия, схема и объяснения обязательны. `value` и `threshold` обязательны даже при значении `0`.

```json
{
  "feature_schema": "weak-signal-features-v1",
  "predictions": [
    {
      "id": "candidate-id",
      "label": "weak_signal",
      "value": 0.82,
      "threshold": 0.75,
      "model": "artifact-name",
      "version": "weak-signal-2026-09-17.1",
      "feature_schema": "weak-signal-features-v1",
      "basis": "Метод объяснения, единицы вкладов и ограничения оценки на русском языке",
      "features": [
        {
          "name": "Название признака по-русски",
          "value": "Наблюдаемое значение",
          "contribution": 0.12
        }
      ]
    }
  ]
}
```

`label`: `weak_signal`, `mature`, `noise`, `failed` или `insufficient_data` — модель воздерживается, данных для решения нет; причину даёт `data_gap` (`not_collected`, `not_found`, `too_early`), и кандидат не исключается. `value` — модельная оценка принадлежности к слабым сигналам в диапазоне [0, 1]. Называть её калиброванной вероятностью можно только после соответствующей проверки. Отрицательный класс или значение ниже `threshold` исключает кандидата с явной причиной. Для прошедших кандидатов модельная оценка задаёт порядок до вспомогательных правил. Панель отдельно считает оценённые моделью карточки и карточки с `value > 0.75`.

Вклады признаков должны соответствовать реальному методу объяснения модели. В `basis` указываются, например, SHAP и единицы log-odds, если именно это рассчитано. Значения из этого примера нельзя выдавать за фактический inference.

Весь пакет проверяется до применения: ошибочный или частичный пакет не создаёт смешанного рейтинга из модельных оценок и правил. Контракт покрыт тестом настоящего HTTP-вызова, включая неверную версию, схему, повтор/пропуск ID, недопустимое число, отсутствие объяснений, нерусское объяснение и недоступность сервиса.

## Что передать вместе с артефактом

1. Неизменяемую версию и контрольную сумму весов, код препроцессинга, зависимости, лицензию и команду запуска.
2. Определение классов и правила разметки. Конкретная технология, общий рыночный показатель и описание атаки должны различаться до оценки ранней стадии.
3. Разделение train/validation/test по технологии, близким документам и времени. Копии источников и одна технология под разными названиями не должны пересекать границы.
4. Precision, Recall, F1, support, матрицу ошибок на независимом тесте; способ выбора порога только по validation. Цель из ТЗ 75–80 % является требованием, а не достигнутым результатом.
5. Проверку утечки: ни итоговый статус, ни экспертное решение, ни жанр источника как фактическая замена класса не должны определять ответ без содержания.
6. Замеры времени inference и памяти на CPU, ограничение входа, поведение при отсутствии признаков и анализ ошибок на зрелых, нерелевантных и слабодоказательных примерах.

После подключения повторяются контрольные отрицательные запросы и ранее не просмотренные направления. Исправление известных примеров не заменяет независимый тест. Отчёт жюри должен отдельно показывать техническую исправность интеграции и качество полученной модели.

## Что классификатор не исправит

Модель не увидит документы и кандидатов, исключённых до неё. Подключение качественного артефакта само по себе не исправит полноту поиска, потерю ограничений исходного запроса, неправильную привязку цитаты или ошибку перевода. Эти дефекты остаются ответственностью нашего продуктового контура и проверяются отдельно от метрик модели.

Живые прогоны находили именно такие ошибки: готовая карточка могла не подтвердить российское происхождение и поведенческую биометрию из запроса; общий педагогический метод прошёл как технология. Нельзя обучать модель на автоматических допусках как на истинной разметке.

Минимум три документа общего механизма — эвристика допуска, а не требование ТЗ
([trend_live_qualification.go](../../backend/main-service/internal/application/trend_live_qualification.go)): исключённое ею единичное раннее наблюдение нельзя
автоматически объявлять шумом.

## Источник кандидатов: сервис extractor

`RADAR_CANDIDATE_SOURCE` выбирает, кто называет технологии в живом поиске по запросу. По умолчанию
(пусто или `ngrams`) — модель генерации (`trend_live_extract.go`) плюс словосочетания заголовков.
Значение `ml` заменяет модель генерации сервисом `extractor` (`POST /extract`) и больше ничего не
меняет: его кандидаты идут тем же путём. Отдельная ветка ML со своим отсевом и карточками давала на
запросах ТЗ английские обрывки фраз или ноль технологий, поэтому `/extract` заменяет только шаг
извлечения. Направления карты и в режиме `ml` идут путём по умолчанию. Устройство сервиса, модели и
бандл весов — [README extractor](../../ml-services/extractor/README.md).

**Включение и откат.** Поднять `extractor` с профилем `ml-extractor` и задать в `infra/.env`:

```dotenv
RADAR_CANDIDATE_SOURCE=ml
RADAR_ML_EXTRACT_URL=http://extractor:8080/extract
RADAR_CLASSIFIER_URL=
RADAR_CLASSIFIER_VERSION=weak-signal-2026-09-23.5
```

`RADAR_CLASSIFIER_URL` в режиме `ml` пуст: оценку даёт встроенная модель, у которой есть метрика на
датасете ТЗ, а `/predict` extractor без признаков `/extract` ставит кандидату 0 % и класс «шум».
`RADAR_CLASSIFIER_VERSION` при пустом адресе классификатор не читает: она служит версией `/extract`
по умолчанию и проверкой бандла — непустое значение, не совпавшее с `service_version` бандла, не
даёт extractor запуститься. Затем `main-service` пересоздаётся точечно
([deploy-stand](../../.claude/skills/deploy-stand/SKILL.md)). Откат — `RADAR_CANDIDATE_SOURCE=ngrams` или
пусто и снова пересоздать. Неизвестное значение оставляет путь по умолчанию; `ml` без
`RADAR_ML_EXTRACT_URL` или версии пишет ошибку в журнал при запуске, и каждый поиск возвращается к
модели генерации.

Остальные переменные: `RADAR_ML_EXTRACT_VERSION` (по умолчанию `RADAR_CLASSIFIER_VERSION`),
`RADAR_ML_EXTRACT_TIMEOUT` (`300s`, не продлевает двенадцатиминутный бюджет поиска),
`RADAR_ML_EXTRACT_MAX_REQUEST_BYTES` (`4194304`) и `RADAR_ML_EXTRACT_MAX_RESPONSE_BYTES`
(`1048576`) — пределы согласованы с Python в Compose. Скорость extractor настраивается без
пересборки образа, значения — в README extractor.

**Кэш.** Режимы хранят поиски под разными ключами (`search-v11|запрос` и `search-v11+ml|запрос`):
переключение флага не затирает ответы другого режима, история показывает ответы текущего. Первый
снимок после запуска пересборку не запускает, поэтому после переключения закреплённые запросы
пересобирают вручную: `GET /api/v1/trends/live/search?q=<запрос>&refresh=1`. Смена версии
извлечения, откат, неполное извлечение и отказ классификатора не дают переиспользовать ответ на
сутки. Поиски `ml` с документами личного корпуса не пишутся в общий кэш: цитата стадии может прийти
из загруженного документа владельца.

**Поиск в режиме `ml`:**

1. Перевод, сбор каналов и окна arXiv — общий путь; только здесь каналы patents/web запрашиваются с
   `?full_text=1` (предел ответа 64 МиБ вместо 8 МиБ), а при переполнении или таймауте — ещё раз
   без текста.
2. Одновременно со смысловым анализом собирается пакет `/extract` (`mlStartExtraction`): документы
   на `ru` или `en`, не больше 240 — столько же читает LLM-извлечение, — ближайшие к запросу (фраза
   терминов в заголовке весит два, в аннотации — один; при равенстве — записи рынка, затем свежие).
   Если в тексте записи нет дословно заголовка или аннотации, они ставятся перед текстом: их ищет
   теггер. Исходные тексты снимаются с записей сразу после сборки пакета и в ответ не попадают.
3. Кандидаты `/extract` становятся входом `extractCandidates` — того же шага, что принимает ответ
   модели генерации. Обрывок, который начинается или кончается служебным словом или оболочкой
   заголовка («…model with», «for generating…»), кандидатом не становится. Одна технология из разных
   документов сливается по имени и дополняется всеми документами, где стоит её имя; меньше двух
   документов — «мало свидетельств».
4. Дальше — общий путь: относимость, проверка сущности, рыночные свидетельства, карточки, пересказы,
   встроенная модель, отбор, добор до пятнадцати.
5. Происхождение из `/extract` (исходное имя, `canonical_ru`, стадия, тренд, флаги шума,
   собственная оценка extractor) остаётся в `candidates[].ml` и `rejected[].ml` и на отбор не
   влияет.

**Отказы.** Пакет больше предела урезается с конца, с самых далёких документов: сначала полный текст
до 20 000 знаков, затем заголовок и аннотация вместо текста, затем документ не отправляется; охват
отмечает `documents_text_truncated`, `documents_text_dropped`, `documents_omitted`. HTTP-ошибка,
таймаут, превышение предела, несогласованная версия или неверный формат `/extract` возвращают
LLM-извлечение с ограничением `ml_extract_fallback`; успешный пустой `candidates: []` остаётся
пустым вкладом. Перенаправления запрещены, повторов нет. `LiveDetail.extraction` фиксирует
`requested`, `used`, `version`, `fallback_reason`, `coverage`, `model_versions`; неполное покрытие
получает `ml_extract_degraded`, пропуск по языку — `ml_extract_language_skipped`.

**Проверка:**

```sh
cd backend/main-service
EXTRACTOR_TEST_PYTHON=<python с ml-services/extractor/requirements-dev.txt> \
  go test ./internal/application -run '^TestLiveML' -count=1
```

Без переменной используется `python3`; без зависимостей два межъязыковых теста `TestLiveMLReview*`
пропускаются. Они передают запросы Go в настоящие обработчики Python через `TestClient`, модели
заменены детерминированными компонентами.
