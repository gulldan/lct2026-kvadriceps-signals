# chunk-splitter

Берёт события `DocumentParsed` из очереди `chunk`, режет разобранный текст на фрагменты,
получает для них векторы и пишет фрагменты с одинаковыми id в Qdrant и OpenSearch для
гибридного поиска. Документ получает статус `indexed` только здесь. Место в конвейере — в
[docs/ARCHITECTURE.md](../../docs/ARCHITECTURE.md).

- Обычный текст режет рекурсивный сплиттер (`internal/infrastructure/splitter`). Если задан
  `TOKENIZER_URL`, бюджет считается в токенах, иначе в символах.
- CSV и TSV сначала нормализуются (`internal/infrastructure/delimited`): строки становятся
  самостоятельными фрагментами с `source_uri=file.csv#rows=...` и повторённым заголовком.
- `page_offsets` из метаданных парсера дают фрагментам диапазоны страниц.
- При заданном `VLLM_URL` модель определяет заголовок документа. `cmd/backfill` проставляет
  заголовки уже проиндексированным документам по их первым фрагментам.
- Пока идут пользовательские запросы (счётчик `rag:active_queries` в Valkey), индексация
  уступает им, но не дольше `INGEST_YIELD_MAX_WAIT`.

## Настройки

| Переменная               | По умолчанию | Смысл                                                                      |
| ------------------------ | ------------ | -------------------------------------------------------------------------- |
| `CHUNK_SIZE`             | 1000         | символов во фрагменте запасного сплиттера                                  |
| `CHUNK_OVERLAP`          | 150          | перекрытие фрагментов запасного сплиттера                                  |
| `CHUNK_MAX_TOKENS`       | 512          | токенов во фрагменте, когда задан `TOKENIZER_URL`                          |
| `SPLIT_WINDOW_MB`        | 8            | окно обработки большого текста                                             |
| `TEXT_MAX_MB`            | 16           | предел разобранного текста                                                 |
| `EMBED_BATCH`            | 64           | фрагментов в одной пачке векторов и записи                                 |
| `CONTEXTUAL_HEADERS`     | true         | приписывать к фрагменту контекст документа и раздела                       |
| `WORKER_CONCURRENCY`     | 2            | документов параллельно                                                     |
| `CHUNK_HANDLE_TIMEOUT`   | 30m          | предел на один документ                                                    |
| `INGEST_YIELD_MAX_WAIT`  | 2s           | сколько ждать, уступая пользовательским запросам                           |
| `SOURCE_INDEX_SNAPSHOTS` | true         | снимки индекса источника; нужны `EMBEDDINGS_MODEL` и `EMBEDDINGS_REVISION` |

## Разделы и локаторы

Снимок источника хранит рядом с фрагментами разделы `sections[{name,title,start,end}]` и
якоря `anchors[{path,start,end}]`. Смещения — в кодовых точках Unicode того текста, который
закрепляет хеш снимка, конец не включается. `name` берётся из общего словаря (`abstract`,
`introduction`, `method`, `results`, `claims` и так далее), `title` — заголовок из самого
документа. `path` — путь элемента HTML (`html/body/article/p[3]`) или номер пункта формулы
(`claim/2`).

Разделы приходят из `section_offsets` парсера, а без них — из того же поиска заголовков, что
размечает фрагменты. Поэтому метка раздела у фрагмента и карта разделов документа не расходятся.
Структура от сборщика, который прочитал настоящее устройство документа (полный текст патента),
важнее найденных заголовков. Структура, которая больше не попадает в сохранённый текст,
отбрасывается, а не подгоняется.

Раздел с описательным названием («3 Denoising in LLM-Oriented Retrieval») имени не получает:
словарь не угадывает, а назвать такой раздел может только модель извлечения.

`locator_kind` фрагмента: `spreadsheet_cell`, `html_element`, `text_span`, `ocr_page` или
`pdf_text_page`. Все локаторы принимает одна функция `indexdoc.Locator.Verify`: текст по
смещениям совпадает с цитатой, иначе локатор отклоняется. `main-service` проверяет так каждый
фрагмент снимка, который отдаёт. pdf-parser не отдаёт координат, поэтому локатор PDF точен
только до страницы.

## Чего нет

- Сайдкары парсеров (`*_sidecar_*` в метаданных `DocumentParsed`) здесь не читаются. Границы
  строк таблицы видны только по `source_uri` в тексте, и один фрагмент на окно строк не
  гарантирован.
- Разбиение с учётом вёрстки PDF, DOCX, PPTX и OCR.
