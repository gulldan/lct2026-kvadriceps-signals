# analysis-freeze

Замораживает вход анализа трендов по корпусу: доступные читателю индексы источников и страницы
сбора на момент отсечки. Ничего не ранжирует и анализ не запускает. Нужны `DB_SERVICE_ADDR` и
`S3_*`.

```sh
analysis-freeze --request request.json --output /новый/input.json
```

Файл `--output` должен быть новым. Отсечка в запросе — UTC и не в будущем.

`collection_scope_ids` (до 16) сужает корпус до конкретных scope сбора этого читателя. Id scope —
64-символьные хеши из отчётов покрытия source-harvester: они фиксируют поставщика, фразу,
категорию, интервал и владельца. Отбор по scope идёт до предела в 2000 документов; права
документа, готовность индекса, даты источника и модель проверяются как обычно. Чужой или
несуществующий scope даёт одинаковый ответ «недоступно». То же поле принимает HTTP-маршрут
анализа.

Выбор scope не доказывает полноту. Воркер всё равно проверяет цепочку курсоров поставщика,
итоги, отклонённые записи и принадлежность источников. Неполный или противоречивый обход
остаётся неполным. Принадлежность документа к scope устанавливается только по сохранённым
манифестам страниц, совпадение названия её не доказывает.
