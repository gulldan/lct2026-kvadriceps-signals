# Проверка перед коммитом

Гоняйте только те половины, которых касалась правка. Все команды — из корня репозитория.

## 1. Очертить свою правку

```sh
git status --short
git rev-parse --abbrev-ref HEAD
```

В чекауте параллельно работают другие сессии. В коммит идут только свои файлы; зоны
разделены в [AGENTS.md](../../../AGENTS.md).

## 2. Фронтенд — если менялись `frontend/**` или `DESIGN.md`

`DESIGN.md` форматирует oxfmt, и pre-commit хук проверяет его формат. Чтобы не задеть чужие
файлы, форматируйте адресно:

```sh
./frontend/node_modules/.bin/oxfmt --config frontend/.oxfmtrc.json DESIGN.md
```

Затем полный гейт (около полутора минут):

```sh
cd frontend && bun run verify
```

Это `fmt:check` → `lint` → `typecheck` → `knip` → `audit` → `test` → `build` → `size`. Юниты
внутри гейта — `bun run test`; голый `bun test` подхватит playwright-спеки из `frontend/tests/`
и упадёт.

Правки дизайн-системы, токенов или UI kit дополнительно закрывает браузерный набор:

```sh
cd frontend && bun run verify:ui
```

## 3. Go — если менялись `backend/**`

```sh
make build
make lint
make test
```

`make lint` идёт по модулям последовательно и **останавливается на первом упавшем**: остальные
модули в этом прогоне не проверены, после починки прогоняйте заново. `make test` на прогретом
кэше укладывается примерно в минуту.

Если линт ругается на файл, которого вы не трогали, — это чужая правка или уже
закоммиченное состояние ветки. Чинить не надо: сказать об этом и оставить как есть.

## 4. Не коммитить

Коммит и push — только по явной просьбе. Правило `//nolint` не обходить: подавление линтера
защищается отдельно.
